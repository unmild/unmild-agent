1 — API keys and third-party providers

Unmild Agent is Bring Your Own Key. We do not host a model, proxy your requests, or issue keys. You paste one or more base URLs and API keys under Settings → Configuration and click Test Connection.

What you paste
Base URL verbatim + API key. Stored in plaintext on disk under %LOCALAPPDATA%\UnmildAgent\. Candidate probe is [base, base + "/v1"] via GET {base}/models.
OpenAI-compatible
POST {base}/chat/completions with Authorization: Bearer <key>. Covers OpenAI, OpenRouter, AgentRouter and any compatible gateway.
Anthropic
POST {base}/messages with x-api-key and anthropic-version: 2023-06-01.
Multiple configs
Each configuration is isolated; switching config switches provider and key. Test must succeed before chat is enabled.
  • You have a direct relationship with each provider. Their terms, pricing, rate limits and privacy policies apply to every request you send.
  • UNMILD cannot see, revoke, rotate or refund provider usage. Effort maps to max_tokens — Low 1024 / Medium 2048 / High 4096 / Ultra 8192 / Max 16384. You control cost.
  • Do not paste keys into screenshots, issue reports or shared transcripts. If a key leaks, rotate it with the provider immediately.
No UNMILD back end. Requests go straight from your device to the base URL you entered via ureq + rustls. We do not log prompts, keys or file content.

2 — Agent autonomy and task execution

The agent is autonomous within the folder you chose. It does not run in a cloud container — it runs as a background thread per project on your Windows device, calling tools as JSON and executing them locally until the model stops.

  • Tools, sandboxed: list_dir, read_file, write_file, delete_file, remember, run_command (PowerShell in the project dir), open_url and screenshot. Filesystem tools reject .. and absolute paths outside the working folder.
  • Turn lifecycle: Model is called via blocking ureq; tool results are fed back and the loop continues. AppState::tick drains progress once per frame. Retries capped at MAX_SEND_RETRIES 12. Stop halts at the next boundary; the thread then idles.
  • Permissions — your gate: Ask first blocks the agent thread on an Approver channel until you allow/deny. Auto-edit permits writes without prompts. Full access permits writes and command execution. Choose per turn.
  • Parallelism & persistence: Multiple projects can run in parallel. The window is tray-persistent via Shell_NotifyIcon; closing the window does not kill threads unless you quit.
  • Memory: remember notes (Smriti) are per-project, injected into the system prompt every turn and survive restarts. Images attached to a prompt are base64-encoded into the chat payload (cap MAX_IMAGE 5 MiB).

You direct the goal; the agent chooses the steps. Review diffs, terminal output and status lines before the next Send — especially on Full access.

3 — User responsibility and permissions

You are responsible for what the agent does with your permission, in your folder, with your keys.

  • Have the right to act. Use only folders, repos, APIs and data you own or are authorized to modify. Do not point the agent at system folders, other users’ profiles, or production without a backup.
  • Keep backups. The agent can read, write and delete files and run PowerShell. Make commits, snapshots or copies before large refactors. UNMILD does not version your files.
  • Approve with care. In Ask first, read the diff and command preview before allowing. In Auto-edit and Full access, you pre-authorize edits and execution — use them only in folders you can restore.
  • Lawful and ethical use only. Do not use the agent to violate law, infringe IP, bypass access controls, generate harassment, or process sensitive personal data without a lawful basis. You are solely responsible for prompts, attached files and resulting code.
  • Credentials hygiene. Scope keys per project, prefer short-lived keys where the provider supports them, and never commit keys to Git. The app offers no cloud vault.
Rule of thumb: if you would not git push it without reading, do not auto-approve it. Pause, inspect the transcript at work-{project}-{run}.jsonl, then continue.

4 — Privacy and credential security

Privacy is local by design. See Privacy policy for the full flow; this section states your obligations.

On disk only
projects.json, history-{id}.sqlite (FTS5 + WAL), work-{project}-{run}.jsonl and Smriti notes under %LOCALAPPDATA%\UnmildAgent\. No sync to UNMILD.
Leaves device only
Inside authenticated requests to your configured base URL — prompts, file excerpts, base64 images and Smriti notes you included.
Site
Static on GitHub Pages. No cookies, no analytics. Google Fonts from fonts.googleapis.com otherwise system fonts.
Keys
Plaintext on disk, never sent to UNMILD. The OS (BitLocker / device encryption, screen lock) is the boundary.
  • Protect the device: enable Windows Update, BitLocker or device encryption, and an auto-lock. Anyone with your Windows profile can read %LOCALAPPDATA%\UnmildAgent\.
  • Minimize context: attach only what the task needs. Redact secrets before attaching. Smriti should hold preferences, not passwords.
  • Deletion is manual: remove the project in-app or delete %LOCALAPPDATA%\UnmildAgent\ for a full wipe. Uninstall alone may not purge that folder.
  • Third-party handling after send is governed by the provider. UNMILD cannot delete data once it reaches them.
